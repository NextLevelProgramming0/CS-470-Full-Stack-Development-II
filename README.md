CS-470 Project Two – AWS Serverless Migration (Summary)

Author: Darius Quick
Course: CS-470 Full Stack Development II
Project Type: Cloud Migration & Serverless Architecture
Format: Presentation (PowerPoint) + Narrated Video

Project Summary

This project documents the migration of a traditional full stack web application to a cloud-native, serverless architecture using Amazon Web Services (AWS). The focus of the project is on explaining design decisions, cloud principles, and security considerations while demonstrating how a full stack application can be modernized for scalability and cost efficiency.

The primary deliverables for this project are a PowerPoint presentation and narrated video, which walk through the migration process, architecture, and outcomes.


Key Topics Covered

Migration from a traditional full stack architecture to AWS serverless services

Use of Docker and Docker Compose during the migration process

Serverless backend implementation using AWS Lambda and API Gateway

Static frontend hosting using Amazon S3

Data modeling and persistence using Amazon DynamoDB

Cloud development principles including elasticity and pay-for-use pricing

Securing cloud resources using IAM roles and policies


Architecture Overview

Frontend: Static assets hosted in Amazon S3

Backend: RESTful API using API Gateway and AWS Lambda

Database: Amazon DynamoDB (NoSQL)

Security: IAM roles, policies, and restricted service access


Learning Outcomes

Gained hands-on experience designing and explaining a serverless architecture

Demonstrated understanding of cloud-native development principles

Practiced defending technical decisions for both technical and nontechnical audiences

Applied AWS security best practices using roles and policies


Project Artifacts

PowerPoint presentation detailing the migration process

Narrated video presentation explaining architecture and design decisions

Career Relevance

This project serves as a portfolio artifact demonstrating real-world cloud migration experience and modern serverless development practices. It is suitable for discussion in interviews when explaining experience with AWS, serverless architectures, and scalable full stack systems.
